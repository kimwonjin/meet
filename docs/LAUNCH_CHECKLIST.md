# 출시 전 체크리스트

실제 사용자를 받기 직전에 아래 순서대로 진행한다. 끝낸 줄은 [x]로 바꾼다.

## 0. SQL이 모두 들어갔는지 확인 (5분)
- [ ] Supabase SQL Editor에서 `supabase/checks/verify_all.sql` 실행
  - 맨 위 줄이 **모두 들어갔어요 (73개)** 면 통과
  - '없음' 줄이 있으면 그 이름을 개발 담당에게 알려 준다 (해당 SQL 파일을 다시 실행)

## 1. 보안 강화 (필수, `docs/SECURITY_PLAN.md`)
- [ ] 모든 표의 "누구나 읽기·쓰기" 접근 규칙(allow-all)을 역할별 규칙으로 교체
- [ ] 탈퇴 번호 흔적(`withdrawn_identities`)은 앱에서 조회하지 못하게 서버 함수로만 처리
- [ ] 알림 서명 키(`push_keys`)·알림 기기 목록(`push_subscriptions`)은 앱에서 못 읽게 막고, `/api/push`는 서버 전용 키로 읽게 변경
- [ ] 사진 보호: 채팅 사진·프로필 사진 주소를 아는 사람만 볼 수 있게 (SECURITY_PLAN ⑤)
- [ ] '여러 회원에게 보내기' 하루 3번 제한을 서버에서도 막기 (지금은 기기마다 셈)

## 2. 테스트 데이터 삭제
- [ ] `supabase/seeds/test_data_reset.sql`의 **1)** 만 먼저 실행해 지울 양 확인

- [ ] **2)** 를 통째로 실행 (중간에 오류가 나면 아무것도 지워지지 않음)
- [ ] 다른 번호로도 테스트했다면 `'010-4444-%'`를 그 번호로 바꿔 한 번 더
- [ ] **1)** 을 다시 실행해 모두 0인지 확인
- [ ] Storage › `profile-photos`에서 테스트 사람 폴더 삭제 (채팅 사진은 `chat/` 아래)
- [ ] 운영자 › 설정 › **전체 백업 내려받기**로 깨끗한 상태를 한 번 받아 둔다
